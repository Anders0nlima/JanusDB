## M1 — Página e arquivo de dados

O M1 implementa a leitura e escrita de páginas de tamanho fixo sobre um arquivo comum, utilizando as operações seek, read e write em modo binário.

Também foi implementada a classe Pager, responsável por manter o arquivo aberto, controlar o número de páginas e realizar operações de leitura, escrita e alocação de novas páginas. O Pager também possui mecanismos de validação e sincronização dos dados com o armazenamento.

Além disso, foi implementada a gravação e leitura de um registro de 8 bytes no slot 0 da página 2. A página 2 começa no byte 8192 do arquivo, pois cada página possui 4096 bytes. Como o cabeçalho ocupa 16 bytes, o registro do slot 0 começa no byte 8208.

Os registros são serializados com struct.pack, transformando os dados do aluno em bytes antes da gravação, e desserializados com struct.unpack durante a leitura. Dessa forma, o fluxo básico é: dados → bytes → arquivo → armazenamento, e depois o caminho inverso para recuperar o registro.

## Principais Dificuldades

A principal dificuldade neste módulo (M1) foi entender como tudo isso é aplicado na prática: como visualizar o dado saindo de uma variável no Python, sendo transformado em bytes e armazenado no arquivo. Também foi necessário entender o papel do Pager, dos offsets e da sincronização dos dados com o armazenamento.

Além disso, foi um desafio pensar defensivamente e projetar validações rigorosas (como verificar se a página lida ou escrita possui exatamente PAGE_SIZE bytes), garantindo que o banco de dados falhe rapidamente (fail fast) em vez de ignorar erros que poderiam causar problemas nas etapas futuras.
