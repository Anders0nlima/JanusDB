# M4 — Parser e catálogo

## Componentes

- `src/tokenizer.py`: converte SQL em tokens tipados e reporta erros léxicos.
- `src/parser.py`: valida a gramática por descida recursiva e produz árvores em dicionários.
- `src/catalog.py`: mantém metadados persistentes em `<arquivo>.catalog.json`, valida tabelas, colunas e tipos.
- `src/engine.py`: executa `CREATE TABLE`, `INSERT` e `SELECT` sobre o `Pager` e `PageCache` existentes.
- `src/cli.py`: REPL para receber comandos SQL do terminal.

## Gramática implementada

```text
comando := (create | insert | select) [;]
create  := CREATE TABLE nome ( coluna {, coluna} )
coluna  := nome INT | nome CHAR ( número )
insert  := INSERT INTO nome VALUES ( valor {, valor} )
select  := SELECT (* | nome {, nome}) FROM nome [WHERE nome = valor]
valor   := número | texto
```

## Limitações atuais

- Uma tabela usa uma página de dados; quando ela enche, o comando `INSERT` retorna um erro claro. A extensão para várias páginas e o uso da B+ são trabalho do M5.
- O catálogo é um arquivo JSON lateral ao arquivo de dados, para preservar sem alterações os formatos binários do M1-M3.
- Não há `UPDATE`, `DELETE`, junções, agregações, `ORDER BY`, nem múltiplas instruções SQL em uma mesma string.
- `CHAR(n)` armazena até `n` bytes UTF-8, preenchendo o espaço restante com bytes zero.
